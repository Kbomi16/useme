# 둘러보기 홈 설계

날짜: 2026-09-17  
상태: 승인됨 · 구현 진행  
범위: `/discover`를 살아 있는 홈처럼 보이게 만들고, 카드에서 가짜 상세 `/project/[slug]`로 이어 준다. Auth·API·진짜 좋아요는 넣지 않는다.

## 1. 배경

랜딩 `/`는 소개 페이지다. 헤더 `둘러보기`가 가는 `/discover`가 실제 홈이다. 지금은 예시 카드 세 장이 같은 그리드에만 있어서, 카탈로그처럼 보이지 않는다.

이번 작업은 패스트캠퍼스 **레이아웃만** 가져온다. 레일, 오늘의 한 장, 밀도 있는 선반, 배지·숫자 알약. 브랜드 빨강·4px 모서리·할인 배너·가짜 카테고리 칩은 복사하지 않는다. useMe 보라(`#7960A9`)와 `rounded-3xl` 카드는 유지한다.

## 2. 목표 (완료 조건)

1. `/discover` 제목은 `둘러보기`다. 레일 설명 문장과 페이지 보조 문단은 없다.
2. 위에 `오늘의 카드` 레일, 자리비움 한 장. 아래에 `최근 카드` 레일, 나머지 여섯 장.
3. 샘플은 일곱 장이다. 모든 카드에 왜/뭘/얼마나 세 칸이 있다.
4. 카드 아래 버튼이 둘이다. `바로 써 보기`(토스트), `설명 보기`(`/project/[slug]`). 카드 전체 클릭은 없다.
5. 좋아요·한마디 숫자는 샘플 데이터에 박혀 있고, 눌러도 안 변한다.
6. 오늘의 카드 아래에만 가짜 댓글 두 줄이 보인다.
7. `/project/[slug]`는 같은 샘플의 읽기 전용 상세다. `바로 써 보기`만 있고 댓글 입력창은 없다.
8. `내 프로젝트 올려보기`는 `/upload`로 간다.
9. `page.tsx`는 Server Component다. 새 애니메이션은 없다.

명시적으로 하지 않는 것:

- 검색, 필터, 정렬, 카테고리 칩, 무한 스크롤
- 로그인, 회원가입, 진짜 좋아요·댓글 저장
- 카드 전체 클릭, 댓글 입력 폼
- 새 일러스트 파일
- 크레딧, 어필력 게이지, 스포트라이트 24시간 로직
- 랜딩에 일곱 장을 모두 보여 주기 (랜딩 샘플은 기존 세 장만)

## 3. 화면 구조

```
AppHeader (기존 둘러보기 / 올리기)
└─ /discover
   ├─ 제목 줄: 둘러보기 | 내 프로젝트 올려보기
   ├─ 레일 오늘의 카드
   │    자리비움 어필 카드 (썸네일 `1` 배지 + 예시 프로젝트 칩)
   │    좋아요·한마디 숫자
   │    가짜 댓글 두 줄
   │    바로 써 보기 · 설명 보기
   └─ 레일 최근 카드
        6장 그리드 (sm:2, lg:3)
        각 장: 어필 카드 + 숫자 + 같은 두 버튼

└─ /project/[slug]
   ├─ 어필 카드 한 장
   ├─ 좋아요·한마디 숫자
   ├─ 가짜 댓글 목록 (2~3줄)
   └─ 바로 써 보기
```

목록으로 돌아가기는 헤더 `둘러보기`만 쓴다. 상세에 뒤로 버튼을 새로 두지 않는다.

## 4. 카피 (해요체, 고정)

| 위치 | 문구 |
| --- | --- |
| 페이지 제목 | 둘러보기 |
| 올려보기 버튼 | 내 프로젝트 올려보기 |
| 위 레일 제목 | 오늘의 카드 |
| 아래 레일 제목 | 최근 카드 |
| 카드 칩 | 예시 프로젝트 |
| 카드 버튼 | 바로 써 보기 / 설명 보기 |
| 상세 버튼 | 바로 써 보기 |
| 토스트 | 로그인은 다음에 붙일게요. |
| 없는 슬러그 | 그 카드는 없어요. |

레일 제목 아래 설명, `다른 사람 카드` 제목, `만져 보고 한마디 남기면 돼요` 보조 문단은 쓰지 않는다.

## 5. 데이터

`sampleProjects`를 일곱 장으로 늘린다. 필드:

- `slug`, `name`, `tagline`, `problem`, `action`, `metric`, `imageSrc`
- `likes: number`
- `comments: { name: string; line: string }[]`

`commentCount`는 `comments.length`로 계산한다. 별도 카운트 필드를 두지 않는다.

오늘의 카드는 배열 첫 장 **자리비움**이다. 선반은 `slice(1)`. 랜딩과 랜딩 목은 `slice(0, 3)`만 쓴다.

## 6. 컴포넌트

서버 페이지가 데이터를 고르고, 클라이언트는 토스트 버튼에만 둔다.

| 단위 | 위치 | 역할 |
| --- | --- | --- |
| `sampleProjects.ts` | `app/_components/` | 일곱 장 + getter. 랜딩도 여기를 읽는다. |
| `AppealCard` | `app/_components/` | 기존 세 칸 카드. `rank`가 있으면 썸네일 왼쪽 위에 `1` 배지. `예시 프로젝트` 칩은 오른쪽 위. boolean `isCompact` 없음. |
| `DiscoverProjectActions` | `app/discover/_components/` | `바로 써 보기`(클라이언트 토스트) + `설명 보기`(Link). |
| `DiscoverSocial` | `app/discover/_components/` | 하트·말풍선 아이콘 + 숫자만. |
| `DiscoverCommentList` | `app/discover/_components/` | 이름 + 한 줄. 입력창 없음. |
| `DiscoverPage` | `app/discover/page.tsx` | 서버. 제목 + 두 레일. |
| `ProjectPage` | `app/project/[slug]/page.tsx` | 서버. 없으면 `notFound()`. `generateStaticParams`로 일곱 장. |

`바로 써 보기`는 상세에도 쓰므로 actions의 토스트 버튼만 클라이언트다. 카드 본체는 서버에 남긴다.

헤더 `max-w-5xl`과 맞추려고 둘러보기·상세도 `max-w-5xl`을 유지한다. 페이지에 카드 밖 드롭섀도를 더 쌓지 않는다.

## 7. 동작

- `바로 써 보기`: `toast.info("로그인은 다음에 붙일게요.")`. 외부 URL로 나가지 않는다.
- `설명 보기`: `/project/{slug}`.
- 좋아요·댓글 숫자는 장식이면 버튼이 아니다.
- 알 수 없는 slug는 `notFound()`. `app/project/[slug]/not-found.tsx`에 `그 카드는 없어요.`와 `둘러보기` 링크.

## 8. 검증

- `/discover`: 제목 `둘러보기`, 오늘 1장, 최근 6장, 각 카드 세 칸 + 버튼 둘.
- 자리비움만 댓글 두 줄.
- `설명 보기` → 상세. 상세에는 `바로 써 보기`만.
- `바로 써 보기` 토스트 문구가 올리기 폼과 같다.
- `/` 샘플 섹션은 세 장 그대로.
- 모바일(375)과 데스크톱(1280)에서 선반이 한 줄에 뭉개지지 않는다.
- 새 GSAP/스크롤 애니메이션이 없다.
